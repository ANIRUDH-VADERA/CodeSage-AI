# INC-1001 Payment timeouts after HTTP timeout was lowered

## Summary
A config change lowered `HTTP_TIMEOUT` in services/payments/settings.py from 2.0 to 0.5 seconds.
The gateway's p99 latency is about 1.4 seconds, so a third of charges timed out. PaymentClient retried
each one, which tripled load on the gateway and caused a retry storm.

## Fix
Rolled the timeout back to 2.0 seconds and capped retry backoff. Any change to the timeout must stay
above the gateway p99.

## Lessons
- Timeouts must be set from measured latency, not guessed.
- Retries without backoff turn a slowdown into an outage.
