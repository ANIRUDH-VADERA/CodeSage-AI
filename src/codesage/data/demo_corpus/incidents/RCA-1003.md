# RCA-1003 Connection pool exhaustion in payments

## What happened
`DB_POOL_SIZE` in services/payments/settings.py was reduced from 20 to 5 to save database connections.
Under peak load, requests waited on the connection pool, hit the HTTP timeout, and were retried, which
held connections even longer.

## Root cause
Pool size was changed without a load test. The hikari-style pool metrics showed 100% utilisation for 40 minutes.

## Actions
- Alert when pool utilisation stays above 80%.
- Pool size changes need a load-test result attached to the PR.
